

# Security Policy

## Supported versions

This repository is primarily educational documentation.

Security-related corrections should be reported for the current version of the repository's content.

| Version | Supported |
|---|---|
| Latest release | Yes |
| Older releases | No guarantee |

## Reporting a vulnerability

If you discover a security issue involving this repository or its maintained resources, please report it privately.

Use GitHub's private vulnerability reporting feature if it is enabled:

1. Open the repository on GitHub.
2. Select the **Security** tab.
3. Look for **Report a vulnerability**.
4. Submit a private report with the relevant details.

If private vulnerability reporting is unavailable, contact the repository maintainer through a private contact method listed on their GitHub profile.

## What to include

Please provide:

- A clear description of the issue.
- The affected file, feature, or workflow.
- Steps to reproduce the problem, where safe.
- The potential impact.
- Suggested remediation, if known.

Do not include real credentials, access tokens, private keys, or personal data in your report.

## What not to do

- Do not publish sensitive vulnerability details in a public Issue.
- Do not test against systems you do not own or have permission to assess.
- Do not access or modify another person's private information.

## Response expectations

The maintainer will review reports and, where possible, acknowledge receipt and provide updates.

This is a community training repository, so response times are not guaranteed.

## Scope clarification

If a lesson contains an incorrect security recommendation, report it as a documentation issue unless it exposes a genuine vulnerability. Use the appropriate reporting method.
